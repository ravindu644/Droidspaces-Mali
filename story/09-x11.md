# 9. X11

X11 apps still rendered on the CPU: `couldn't get an RGB, Double-buffered visual`. Xwayland had no GPU, and libhybris has no Vulkan X11 surface. Five problems stood between them and the Mali.

## 1. The Mali can't export memory

Xwayland's glamor allocates buffers through Zink's GBM and shares them as dma-bufs. Zink then fed stack garbage to `drmPrimeFDToHandle()` and failed with `EBADF`.

A probe of the Mali's external memory support showed why: `VK_EXT_external_memory_dma_buf` is import only, and `vkGetMemoryFdKHR()` returns `VK_SUCCESS` without writing an fd. The Mali can use a dma-buf, but it can't make one.

**Patch 21** emulates export, the way [bionic-vulkan-wrapper](https://github.com/leegao/bionic-vulkan-wrapper) does: memory that must be exportable is allocated from `/dev/dma_heap/system` and imported into the Mali, which renders into it correctly. `vkGetMemoryFdKHR()` hands out a duplicate of that fd.

## 2. kopper needs a Vulkan X11 surface

GLX crashed calling NULL. Zink's kopper presents through a Vulkan surface, and libhybris has none for X11. Mesa's older DRI3 path doesn't need one: Zink renders into exported dma-bufs and Mesa presents them.

`LIBGL_KOPPER_DISABLE=1` would turn kopper off for Wayland too, and Wayland EGL then falls into a broken software path. **Mesa patch 3** adds `LIBGL_KOPPER_DISABLE_X11`, which only GLX and EGL on X11 read. One environment then serves both kinds of app.

## 3. X11 apps died after about 1000 frames

Every frame, Zink exports a sync file from the dma-buf with `DMA_BUF_IOCTL_EXPORT_SYNC_FILE`. Kernels before 6.0 don't have that ioctl, and Mesa 25.0.7 didn't close the dma-buf fd when it failed. After about 1000 frames the process ran out of fds and the device was lost. **Mesa patch 1** is the upstream fix, backported.

## 4. glxgears crashed in pipeline creation

A gdb script logging every pipeline Zink created caught the crash: Zink's own geometry shader for emulating quads, with `LINE_LIST_WITH_ADJACENCY` topology. Geometry shaders written by apps build fine on the Mali. Only the ones Zink generates crash its compiler, and bisecting their SPIR-V by hand didn't find the instruction.

**Patch 22** adds `HYBRIS_VK_HIDE_FEATURES`. With `geometryShader` hidden, Zink splits quads on the CPU instead. The cost is the OpenGL 3.2 and OpenGL ES 3.2 ceiling, see [Still open](README.md#still-open). On the way we also backported **Mesa patch 2**, which wasn't the cause.

## 5. Xwayland's environment

KWin starts Xwayland, so Xwayland inherited KWin's libhybris EGL environment. A wrapper first in KWin's `PATH` gave it the app environment. It's gone now, see [Daily driving](10-daily-driving.md).

glxinfo then reported direct rendering on `zink Vulkan 1.3(Mali-G57 MC2)`. glmark2 over X11 scored 243, with refract at 110 fps instead of 8.

## A real game: Chromium B.S.U.

An SDL game with fixed-function OpenGL, the kind of app that finds the gaps.

**It flickered and crashed.** `apt install` ran `ldconfig`, which linked the `libGLX_mesa.so.0` soname to a backup we had left next to the patched library, `libGLX_mesa.so.0.0.0.deb-orig`. GLX took kopper again and crashed. `ldconfig` treats any `lib*.so*` file in a library directory as a candidate, whatever comes after `.so`. The same thing had silently put the stock KWin back, with its fade blink, through a `.pkg` backup. Mesa is a real package now, built with the patches, so there are no backups to trip over.

**It looked torn: mixed blocks, missing text and glow.** It wasn't sync. llvmpipe through the same Xwayland and KWin rendered it correctly. apitrace settled it: record the game on llvmpipe, replay one frame on both drivers with `glretrace -S`, and diff the images. The textures were wrong.

Small probes narrowed it down. Fixed-function texturing lost linear filtering and sampled the wrong mip level, while GLSL's `texture2DProj` was fine. Zink had split the fixed-function shader's texture coordinate input into two variables at one location, the second with `Component 3`, and the Mali compiler reads such a split input wrongly. **Mesa patch 4** keeps those inputs whole. The game rendered correctly.

## OpenGL ES 3.1

Mesa only offers OpenGL ES 3.0 and later with instanced arrays, which Zink tied to `VK_EXT_vertex_attribute_divisor`. The Mali has no divisor extension, but core Vulkan's per-instance input rate already is a divisor of 1. **Mesa patch 5** advertises divisors and treats any above 1 as 1, with a warning. OpenGL ES went from 2.0 to 3.1, and glmark2-es2-wayland went up to 133.
